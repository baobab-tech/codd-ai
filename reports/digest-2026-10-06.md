## Findings (session discoveries)


### access_patterns

- The Canadian Open Data Directory has no API or download. Its 253 org records are a CSV string embedded in the site's SvelteKit JS bundle; the bundle also links two Google Sheets that look like the upstream editing source. _(project:directory; claude 2026-10-04; https://directory.opendatasociety.ca/directory)_
- 42 orgs have no catalog API the probe recognizes. They fall into: documented non-catalog APIs (StatCan WDS, Bank of Canada Valet, GeoNetwork, FRDR, geo.ca), Esri map servers without Hub, static pages linking files, JS apps hiding a backend API, PDF libraries, and pages that aren't data sources. _(project:; claude 2026-10-04; docs/PLAN.md#non-standard-sources)_
- National/federal orgs have the lowest API coverage in the directory (2 of 8): StatCan, Bank of Canada, CMHC, Elections Canada and geo.ca each use bespoke APIs or download pages instead of a catalog platform. _(project:; claude 2026-10-04; pnpm digest (API coverage by org type))_
- Statistics Canada's directory link is a web listing, but its Web Data Service (WDS) REST API lists 8,271 data tables in one call, offers full-table CSV download per table, and supports point queries by vector or coordinate. It is the most agent-friendly federal source found so far. _(source:statcan_wds:www150.statcan.gc.ca; claude 2026-10-04; https://www150.statcan.gc.ca/t1/wds/rest/getAllCubesListLite)_
- Red Deer runs a custom portal with a clean paged JSON API per dataset (skip/take, totalCount, metadata endpoint) and CSV/Excel/JSON downloads. No fingerprint can find it; it surfaced only by reading a dataset page. Bespoke portals can still be highly agent-friendly. _(source:reddeer_api:data.reddeer.ca; claude 2026-10-04; https://data.reddeer.ca/api/datasets/building-permits?skip=0&take=1)_
- Auto-profiling the 37 sources without a recognized catalog API: 7 resolved automatically (Hub sites linked from a city page, ArcGIS Servers with an open-data folder, Elections Canada as an organization inside open.canada.ca), 19 need an agent to verify (11 script-heavy sites to inspect in a browser, 5 orgs to locate inside shared portals, 3 file listings), 11 need a human (5 document-heavy sites, 4 pages with no data found, 1 ArcGIS folder choice, 1 unreachable). _(project:; claude 2026-10-04; pnpm autoprofile 2026-10-04)_
- City and agency 'open data' pages often link out to the real portal on another host (an ArcGIS Hub site, a provincial CKAN). Directory URLs that point at a city web page rather than the portal hide the API from fingerprinting. _(project:; claude 2026-10-04; autoprofile observations)_
- Of 8 sources the auto-profile linked to a shared portal or a file listing, all 8 turned out to be file listings on the publisher's own site (AMO, Tribunals Ontario, Whitehorse, NWT Geomatics, Manitoba Land Initiative, London Transit, OEB, Sault Ste. Marie). The shared-portal link was a reference in every case. _(project:; claude 2026-10-06; needs_review batch 2026-10-06)_
- London Transit publishes a GTFS static feed and GTFS-realtime feeds as JSON (trip updates, alerts, vehicle positions), so its data is live-queryable. _(source:web:www.londontransit.ca/open-data; claude 2026-10-06; http://gtfs.ltconline.ca/Vehicle/VehiclePositions.json)_
- Sault Ste. Marie publishes its open data as CSV files on GitHub Pages. _(source:web:cityssm.github.io; claude 2026-10-06; https://cityssm.github.io/)_
- 15,083 resources in the CKAN portals are loaded into the CKAN DataStore and can be queried row by row through datastore_search, with no file download. _(project:; claude 2026-10-06; resources.datastore)_
- The Bank of Canada's Valet API lists 16,173 time series in 2,549 groups and returns observations as JSON, CSV or XML. _(source:valet:www.bankofcanada.ca; claude 2026-10-06; https://www.bankofcanada.ca/valet/lists/series/json)_

### bot_blocking

- Données Québec sits behind AWS WAF bot control. HTML pages answer 202 challenge pages under repeated requests and stay challenged even with a browser user agent, while the CKAN API on the same host answers normally. Agents should use the API, not the pages. _(source:ckan:www.donneesquebec.ca; claude 2026-10-04; probes check=root server=awselb/2.0)_
- Figshare's search pages sit behind AWS WAF and return challenge pages to scripted clients; its documented REST API (api.figshare.com/v2) is the access path. _(org:figshare-research-open-data; claude 2026-10-04; https://figshare.com/search?q=Canada)_
- Open Hamilton (ArcGIS Hub) puts its catalogue API behind a Cloudflare managed challenge for every scripted client, regardless of user agent. Agents cannot use it, unlike Données Québec, whose WAF exempts the API. _(source:arcgis_hub:open.hamilton.ca; claude 2026-10-06; https://open.hamilton.ca/api/search/v1/collections/dataset/items)_

### connectors

- ArcGIS Hub sites expose two catalog endpoints: the OGC search API (/api/search/v1) and a DCAT-US feed (/api/feed/dcat-us/1.1.json). The feed still works on some sites where search is broken. _(connector:arcgis_hub; claude 2026-10-04; src/cli/probe.ts)_
- Profiling pilot of 5 non-standard sources: 1 was a catalog platform the probe didn't know (GeoNetwork), 2 were bespoke APIs (StatCan WDS, Red Deer), 1 an Esri server (Banff), 1 a static file listing (Saanich). None was a document library or a JS-only app. _(project:; claude 2026-10-04; pilot 2026-10-04)_
- Only the directory sync adapter is Canada-specific. Probe, fingerprints, auto-profile, review queue, findings and digest work for any meta-catalog of portals. _(project:; claude 2026-10-04; docs/PLAN.md)_
